# Cassie v2 架构：原版界面 × 新运行时

## 结论

原版 Cassie（YukiMeta/Cassie，`apps/web`）有完整的产品骨架：主体列表与生命周期、锁、Agent 指令框 → Harness 状态机 → 提交、BYOK 模型、SAM 提取、关键帧、切分删除、撤销重做。但它只能对「整段 clip」做事：主体替换是 CSS 色相，导出不应用，提取得到的框被丢弃。

本分支补上的运行时能力：本机物体识别、逐帧跟踪、主体区域（SubjectRegion）挂在时间轴上、跨镜头同一实体、局部替换对齐、服务端渲染、物体级合成。若只用新客户端而丢掉原版界面，会同时丢掉主体列表、指令框、锁与 Harness UI。

v2 方向：**原版界面做产品壳，新运行时做引擎，一份工程文件，一条任务队列，一个常驻视觉服务。**

## 两个验收任务

A. 多镜头成片：导入后全片索引某一产品主体的每一处出现 → 一条指令换成另一产品 → 每处只换物体像素 → 审核 → 导出。

B. 单镜头手持产品：识别出手持产品为独立主体 → 在画布上点选 → 直接改（颜色等）或输入指令替换 → 物体以外的像素完全不变。

每个里程碑都以这两个任务在浏览器里真实点通为验收，而不是以成片为验收。

## 分层

1. 界面层（`apps/web`）：Topbar / Sidebar 主体列表 / Stage 画布 / Timeline / AgentPanel / SettingsModal。
2. 客户端状态（`apps/web/src/store.ts`）：从运行时 API 读写 EventWorkspace；撤销重做走服务端事务。
3. 运行时 API（`packages/runtime`）：工程读写、编辑事务、`/scene` 预览、任务队列（detect / track / mask / generate / composite / render）。
4. 内核（`spec` + `harness`）：EventDocument 为唯一事实源；SemanticEntity 绑定 SubjectRegion；DocumentEdit 事务与回滚。
5. 视觉服务（常驻进程）：模型只加载一次。`/extract`、`/detect`、`/mask`、`/composite`；设置里的「服务地址」指向它。
6. 生成供应商（用户自配进程 / BYOK）：只接收物体窗口与参考图，产出候选；候选永远经过物体级合成再进入工程。

## 主体编辑闭环（任务 A、B 共用）

1. 识别：候选框叠在画布上；或「从视频提取主体」跨全片提取。
2. 认领：点框 → 跟踪整段镜头 → SubjectRegion（逐帧框 + 掩码）→ 同名实体跨镜头合并。
3. 选中：画布命中区域选中主体，而不是整段镜头；列表、时间轴、右侧面板同步。
4. 直接修改：颜色、强度、羽化、显隐，只作用在掩码内。
5. 指令修改：输入替换意图 + 可选参考图 → 计划显示每一处出现 → 生成候选 → 物体级合成 → 逐处审核。
6. 导出：渲染使用合成后的镜头媒体，预览与导出一致。

## 关键技术决定

- 物体级合成：只贴物体像素并羽化，不允许整块矩形覆盖。
- 掩码按 sha256 引用进 media，可复验。
- 超过约 1 秒的操作都是 job，有进度、可取消、结果作为事务写回。
- `apps/web` 以 EventDocument 为事实源；LocalAdapter 仅保留离线演示。

## 里程碑

M1 统一底座：`apps/web` 接运行时 API，主体列表来自 entities + regions，时间轴拖动写回事务。

M2 视觉服务常驻：检测与分割模型常驻，任务队列与进度推送；「从视频提取主体」接上。

M3 画布点选与直接修改：掩码命中、选中联动；颜色等只作用在物体掩码内。验收任务 B 的直接修改部分。

M4 指令替换：计划 → 生成 → 物体级合成 → 审核 → 写回。验收任务 B 完整通过（框外像素差异为 0）。

M5 全片索引与批量替换：多镜头导入、跨镜头实体合并、一条指令批量替换。验收任务 A。

## 质量保障

- 每个里程碑：类型检查、单元测试、运行时集成测试、浏览器端到端脚本。
- 像素守恒检查：替换后对比原片，物体掩码外像素差异必须低于编码噪声阈值。
- 每一步结果写进工程历史，可回滚。

## 保密与剪枝

- 不入库：真实样片、候选生成结果、密钥、内部模型名与供应商配置、绝对本机路径。
- 公开仓库只保留工程代码、脱敏 fixture、产品架构说明。
