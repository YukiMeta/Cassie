# Cassie

## 像编辑图层一样编辑视频

每一个用 AI 生成过视频的人，大概都经历过这个瞬间：

Sora、可灵、Runway 或 Vidu 帮你生成了一段漂亮的 15 秒视频。整体看起来不错，只剩三个小地方要调。

你想把产品出现的时间提前 2 秒。

但你发现，视频里的香水瓶没有名字。

它没有上场时间，没有退场时间。它只是几百帧画面里的一团颜色。你选不中它，也没法告诉它“早点出来”。

你想把香水瓶从紫色改成蓝色。

但你发现，改颜色意味着重新生成整段视频。你输入新的 Prompt，按下生成，然后祈祷：人物的脸不要变，构图不要崩，音乐节奏不要错位。

你想换个背景，人物和产品原地不动。

但你发现，这几乎不可能。模型眼里没有“人物”和“背景”，只有一张一张完整的画。拆不开。

最后，你花了三个小时反复生成、反复赌。对着预览页沉默了一会儿，回到对话框里，打出那行字：

算了，再抽一次吧。

这是 AI 视频时代最荒诞的体验：

生成一段视频越来越容易，修改一段视频却依然像赌博。

你只想改一个地方，却不得不重新赌一次整个视频。

## 为什么照片可以改，视频不能

在 Photoshop 或 Figma 里，我们从来不怕修改。

想改一个元素，点它。想换一张图，拖一张新的进来。想挪个位置，动一下鼠标。想删一个图层，其他图层纹丝不动。

自然到我们忘了，这套操作背后有图层系统在撑着。

图层系统的本质，是每样东西都有名字。

这个图层叫“香水瓶”，那个图层叫“人物”。它们各自独立，改其中一个，另一个纹丝不动。

视频里没有这种东西。

今天大多数 AI 视频的工作流只有三步：

```text
用户意图 → Prompt → 视频
```

你和最终视频之间，只有一行 Prompt。

第一次生成时，这条路足够快。等你需要修改时，问题就来了：

Prompt 被重新理解，模型被重新调用，每一帧被重新生成。你原本满意的部分——表情、运镜、卡点——也跟着变。

每一次修改，都是一次盲盒重抽。

这不是你不会写 Prompt，也不全是模型不够聪明。是这条路缺了一层：让每样东西都有名字的中间层。

## 老剪辑软件：有皮，没有骨

传统剪辑软件把时间管得很好。第几秒、第几帧，分毫不差。

但它们本质上只有两层能力。

第一层是“皮”。

画面、声音、字幕、转场、特效，都是我们直接看得见、摸得着的部分。这一层，传统剪辑软件做得足够好——精确到帧的裁剪、拼接、调色、混音。

第二层是“骨”。

谁是什么时候出现的？产品从第几秒到第几秒可见？人物和产品之间是什么关系——手持、注视，还是各自独立？删掉一个镜头后，后面的主体状态要不要变？

这些，传统剪辑软件并不知道。

Premiere 和 Final Cut 知道怎么把片段拼在一起。但编辑器并不知道：

- 画面里的香水瓶和旁边的手，是不是同一个互动关系；
- 删掉一个镜头后，产品首次出现的时机要不要重排；
- 改产品颜色时，人物的肤色、环境的反光要不要跟着变；
- 主体提前上场时，音乐卡点和构图应该让路还是保持；
- 哪些是内容结构，哪些只是当前的视觉风格。

于是答案浮出来：

视频缺的不是另一个生成器，而是一套看得见、读得懂、改得动的语义结构。

## 给视频里的每样东西，起一个名字

视频里的东西，应该有自己的档案：

- 它是什么——人物、产品、Logo、场景，还是背景装饰；
- 它从哪一秒上场、哪一秒退场——这是它的生命周期；
- 它和别的东西什么关系——手持、注视，还是互不相关；
- 它有什么不能动——锁。

这就是我们要在视频之上建立的中间层：**Semantic Graph**，一棵语义结构树。

叶子是像素，枝干是主体和它们的关系。

有了这层结构，修改就从“重新生成”变成“找到它，改它”：

- 产品变色时，系统知道环境反光要不要跟着变；
- 主体提前 2 秒上场时，系统知道音乐卡点要不要让路；
- 删掉一个镜头后，系统知道后面镜头的状态要不要重排。

一句话：

**改主体，不伤关系；改关系，画面自动重排。**

改视频，从抽卡变成点名。

## 生成这一局已经赢了，我们赌下一局

市面上不缺“从零生成”的工具。

我们不打算和它们赌同一局。

Cassie 只解决一个问题：

当你已经有了一份基本满意的视频，怎样像编辑图层一样，稳定地只改其中一部分？

它的工作路径是这样的：

```text
已有视频 / 剧本 / 分镜
        ↓
导入并解析语义结构
        ↓
生成 Semantic Graph（主体 · 生命周期 · 关系 · 锁）
        ↓
用户直接操作或输入修改指令
        ↓
Harness 状态机接管：绑定 → 追踪 → 影响分析 → 约束检查 → 编译 Patch → 提交
        ↓
传播必要的级联约束
        ↓
只重新生成受影响的主体和帧
        ↓
局部更新视频
```

这里最重要的不是 Semantic Graph 这个词，而是两个字：

**局部。**

不是重新生成整段视频，不是全帧搜索替换，也不是让模型再自由发挥一次。

系统会把你的修改定位到具体主体，只更新受到影响的部分。

改哪里，就动哪里；动哪里，就只重算哪里。

模型负责生成，Harness 负责不把视频改坏。

所以 Cassie 不是又一款视频生成器。它是编辑器——带生成能力的语义编辑器。

## 第一版，先做好六件最常用的事

我们不打算在第一版里做一个无所不包的编辑器。

只做六件最常见、也最让人痛苦的视频修改：

### 1. 选中主体，直接修改

点击视频里的任何一个语义主体——人物、产品、Logo 或场景。系统知道它是什么、从哪一秒到哪一秒存在、和谁有关系。直接对它下达指令，不用重新描述整个视频。

### 2. 调整生命周期，时间线自动跟随

每个主体都有一条可拖动的生命周期轨道。想让产品提前 2 秒上场？直接拖动它的进场时间。系统自动重算关联镜头的构图、互动关系和状态轨，音乐卡点等锁定内容纹丝不动。

### 3. 局部替换，保留原有关系

把香水瓶换成磨砂银瓶。系统在整个生命周期里保持产品身份一致——从人物手中到 Hero Packshot 特写，始终是同一个商品。换的是外观，不是视频。

### 4. 锁定保护，改了的不被改坏

人物身份、品牌 Logo、音乐节奏——这些你已经满意的部分，一键锁定。系统编译补丁时自动检查硬锁约束。你改的是瓶子颜色，人物的脸不会变。

### 5. 级联传播，修改自动联动

改完一个主体，系统自动算级联影响：产品变色了，手持关系要不要重查？Hero 镜头的构图要不要重排？状态轨要不要更新？不用你手动追踪，Harness 状态机替你完成。

### 6. 大幅运动交给 AI，小幅调整直接拖动

简单的进出场调整和时间平移，直接在时间轴上拖，确定性操作，不需要模型参与。大幅运动轨迹变化或视觉风格重构，一键交给 AI——但生成范围严格限定在受影响的主体和帧内，不波及全片。

## 甜点：名字，可以跨项目活着

结构明确之后，还有一件更有意思的事：

长期资产库。

人物有三视图、声音和身份 DNA，产品有包装版本、Logo 纹理和材质参考，场景有环境光照和空间布局。这些资产通过 `@Mia`、`@Nocturne_Bottle` 这样的名字引用，跨项目可用。

同一个 `@Mia`，从 A 项目走到 B 项目，脸还是那张脸；同一个瓶子，换一条广告，材质不会变。

这很像设计系统里的组件库。

也是我们理解的视频资产系统：

**换场景不换身份，改创意不改资产。**

## AI 让生成变得廉价，也让修改成为新的稀缺

过去，做视频最难的是从零开始。

现在，生成已经便宜了。贵的、难的，是改。

用户要的不只是一个看起来不错的初稿。

用户还要能继续调整它、打磨它、控制它，让它最终准确表达自己的意图。

这也是为什么，我们研究这些藏在体验背后的东西——Semantic Graph、Harness 状态机、局部补丁、级联传播。

因为一个好用的视频编辑器，不在于让你看见它什么都能生成。

而在于让你相信：

**我做的每一次修改，都不会毁掉已经满意的部分。**

像编辑图层一样编辑视频。

这一次，你不需要从头再来。

你只需要把那段差点进回收站的视频重新打开，选中你想改的那个东西。

这一次，其余的纹丝不动。
